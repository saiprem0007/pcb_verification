# DATA.md — How to add real inspection images

> **IMPORTANT** Every number in this file that comes from synthetic data is
> labelled `[SYNTHETIC]`. Those figures are smoke-test results only and must
> not be quoted as real-world accuracy evidence.

---

## Folder layout

```
data/
  datasets/
    <dataset_name>/
      manifest.json          ← required (see template below)
      images/
        good_01.jpg          ← GOOD boards
        defect_missing_R17.jpg
        review_blurred.jpg
      split_manifest.json    ← generated by split_dataset.py (optional)
```

`<dataset_name>` is a short slug, e.g. `pcb_line1_2025q4` or `box_pilot_01`.

---

## Naming conventions

Files under `images/` can be named freely — the manifest is the source of truth
for labels.  The **filename-prefix fallback** (no manifest) still works for
quick experiments:

| prefix       | inferred label |
|---|---|
| `good_*`     | GOOD |
| `defect_*`   | DEFECTIVE |
| `review_*`   | REVIEW |

Use descriptive names for real images so logs are readable:
`defect_missing_R17_2025-11-04_unit042.jpg`.

## manifest.json template

```json
{
  "dataset": "my_dataset",
  "reference_id": "PCB_MODEL_001",
  "source": "real",
  "note": "Line 1 pilot run, week 44/2025. Camera: GigE 5MP.",
  "images": [
    {
      "file": "images/good_001.jpg",
      "label": "GOOD",
      "source": "real",
      "expected_defects": [],
      "note": "verified clean by QC"
    },
    {
      "file": "images/defect_missing_R17_unit042.jpg",
      "label": "DEFECTIVE",
      "source": "real",
      "expected_defects": [
        "R17:MISSING_COMPONENT"
      ],
      "note": "resistor R17 missing, confirmed by rework station"
    },
    {
      "file": "images/defect_shifted_C4_unit051.jpg",
      "label": "DEFECTIVE",
      "source": "real",
      "expected_defects": [
        {"ref_des": "C4", "type": "SHIFTED_COMPONENT", "bbox": [120, 80, 32, 18]}
      ],
      "note": "C4 shifted 12 px east; bbox [x,y,w,h] in reference-px"
    },
    {
      "file": "images/review_blurred_unit007.jpg",
      "label": "REVIEW",
      "source": "real",
      "expected_defects": [],
      "note": "camera autofocus failed; human review needed"
    }
  ]
}
```

### Required fields per image

| field | type | required | notes |
|---|---|---|---|
| `file` | string | **yes** | relative path from dataset root |
| `label` | string | **yes** | `GOOD`, `DEFECTIVE`, or `REVIEW` |
| `source` | string | **yes** | `real` or `synthetic` |
| `expected_defects` | array | **yes** | empty `[]` for GOOD/REVIEW; strings `"REF_DES:TYPE"` or dicts for DEFECTIVE |
| `note` | string | no | free-text; human description |
| `stage_id` | string | no | stage the image belongs to (e.g. `smt`, `final`) |
| `product` | string | no | product_id (links to stage model) |
| `split` | string | no | `tuning` or `heldout`; assigned by `split_dataset.py` if absent |

### Valid defect types (for `expected_defects`)

```
MISSING_COMPONENT
SHIFTED_COMPONENT
ROTATED_COMPONENT
SIZE_DEVIATION
VISUAL_ANOMALY
WRONG_COMPONENT
UNEXPECTED_COMPONENT
```

Format: `"REF_DES:DEFECT_TYPE"` (compact string) **or** dict:
```json
{"ref_des": "C4", "type": "SHIFTED_COMPONENT", "bbox": [x, y, w, h]}
```
`bbox` is `[x, y, width, height]` in reference image pixels, optional.

## Stage-aware datasets

If your product has multiple inspection stages, add `stage_id` to each image
and the manifest becomes stage-filterable:

```json
{"file": "images/smt_good_001.jpg", "label": "GOOD",
 "source": "real", "stage_id": "smt", "expected_defects": []}
```

Then evaluate per-stage:
```
py scripts/evaluate.py --dataset my_dataset --stage smt
py scripts/evaluate.py --dataset my_dataset --stage final
```

## Workflow for adding a new real-image batch

```bash
# 1. Create the folder and copy images
mkdir -p data/datasets/my_dataset/images
cp /path/to/images/*.jpg data/datasets/my_dataset/images/

# 2. Write manifest.json (from template above)

# 3. Validate the manifest loads correctly
py -c "
import sys; sys.path.insert(0,'scripts')
from harness import load_manifest
from pathlib import Path
m = load_manifest(Path('data/datasets/my_dataset'))
print(f'{len(m.images)} images loaded OK')
"

# 4. Assign tuning/heldout splits (dry-run first)
py scripts/split_dataset.py --dataset my_dataset --dry-run
py scripts/split_dataset.py --dataset my_dataset --seed 42 --heldout-frac 0.3

# 5. Evaluate
py scripts/evaluate.py --dataset my_dataset --split tuning
# hold back --split heldout until acceptance criteria confirmed
```

## Minimum dataset sizes (PROPOSED — awaiting user confirmation)

See [ACCEPTANCE.md](ACCEPTANCE.md) for the proposed numeric targets.

As a rough guide:
- **Smoke test** (synthetic): ≥10 images (current synthetic_v1)
- **Pilot / tuning**: ≥50 real images (≥20 DEFECTIVE) before quoting metrics
- **Heldout evaluation**: ≥30 images (≥10 DEFECTIVE), never touched until acceptance gate
- **Production release gate**: TBD — see ACCEPTANCE.md

---

## What NOT to do

- Do **not** edit `split_manifest.json` by hand after splits are assigned.
- Do **not** add an image to both `tuning` and `heldout` splits.
- Do **not** mix synthetic and real images in the same dataset without
  separate `source` labels. The harness reports them separately.
- Do **not** quote synthetic evaluation numbers as real-world accuracy —
  they are smoke tests.
